# v1.4.2 暂停、继续与重新翻译

翻译主按钮下方新增「暂停」和「重新翻译」。原来的「翻译此页 / 还原本页」与「重试失败段落」继续保留。

| 操作 | 行为 |
| --- | --- |
| 暂停 | 保留已显示的译文，取消正在请求和后台排队中的翻译；按钮变成「继续」。暂停期间滚动或新增页面内容，也不会发送新的翻译请求。 |
| 继续 | 从暂停位置的上一段重新翻译，随后接着处理未完成内容。更早的成功译文保持原样，不重复包裹或插入。 |
| 重新翻译 | 取消上一轮任务、清除本页译文、回到页首，从第一段重新请求全部段落；跳过旧缓存，完成后写入新缓存。暂停状态下也可以直接重译。 |
| 还原本页 | 取消任务，移除译文和包裹节点，结束当前翻译。 |

关闭再打开插件面板会保留当前网页的暂停状态。已经全部完成时，「暂停」不可用；「重新翻译」仍可使用。

## 暂停位置

请求存在并发，某个较后的段落可能先返回。暂停时，以文档顺序中最早仍在请求或排队的段落作为停止位置，从其上一段补接，避免跳过尚未完成的段落。如果没有在途或排队任务，则使用首个等待进入视口的段落；如果停止位置就是第一段，继续仍从第一段开始。

普通翻译和继续保留原来的懒翻译行为。重新翻译则按文档顺序处理本页全部已识别段落，保持最多两个并发请求。

## 请求与结果隔离

- 每一批请求有取消信号。内容脚本通过 `requestId` 通知后台取消；后台按标签页与 frame 区分请求，移除排队任务或中断 fetch、退避等待。
- 单个页面暂停不会把其他页面共享的接口探测一并取消。被取消的任务不自动重试、不计入失败。
- 管线为每次暂停、还原递增代次。即使某个传输层不支持中断，旧结果晚到也不会渲染或修改新一轮的统计。
- 继续时重新处理上一段会原位替换译文；原文与更早的译文节点保持不变。
- `paused`、`canPause`、`waiting` 随进度传给弹窗。暂停状态保存在网页控制器中，独立于面板的打开与关闭。

## 验证

从项目父目录启动端口 8766 的静态服务器，再从项目目录运行：

```bash
python3 test/verify_reliability.py --ext .
```

`test/controls.js` 使用可控的延迟响应验证暂停位置、取消、晚到结果、连续点击、懒翻译、增量内容和完整还原。真实扩展集成测试通过延迟模拟 API 验证按钮交互、关闭后重开面板、继续翻译、缓存跳过、从第一段重译，以及暂停状态下发起新一轮重译。测试使用隔离 Chrome 配置，不读取用户密钥。

2026-11-05 验证：42 项可靠性检查全部通过（包含原有 67 项 DOM 测试）、35 项 API 兼容性断言通过、原有弹窗操作检查全部通过。实际安装的 Chrome 扩展已重新加载为 1.4.2，并使用真实模型验证了「重新翻译 → 暂停 → 继续」流程。
